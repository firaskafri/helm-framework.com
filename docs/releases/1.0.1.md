## Scope and compatibility

This is a meaning-preserving hardening release: provenance and explicit limitations, accessible progressive enhancement, content safety, static deployment and automated checks. Existing principles, models, thresholds and role guidance retain their baseline meaning and canonical anchors. Proposed semantic corrections are recorded separately in `docs/corrections.md`.

The application package remains `0.0.1`. The build stack moves from Astro 6 to Astro 7.3.3 to resolve audited dependency vulnerabilities. The remark pipeline is explicitly selected to preserve Markdown/MDX behavior and apply accessible table/task-list transforms. Runtime deployment changes from Node/port 80 to static nginx/port 8080; see `docs/deployment.md`.

## Accessibility and performance scope

Automated checks target WCAG 2.2 A/AA rules available in axe, keyboard interactions, responsive widths 1280/390/320, reduced motion, print and JavaScript-disabled access. Interactive behavior is checked in Chromium, Firefox and WebKit. These checks do not constitute an independent screen-reader audit or blanket WCAG certification.

Budgets: each HTML page at most 400 KB; total built JavaScript at most 75 KB gzip; total CSS at most 100 KB gzip. Measurements are artifact sizes, not field Core Web Vitals. Google Fonts/network and production-host timings require deployment-level observation.

Verified production output: 20 HTML pages, 44 generated files; 4,180 bytes of JavaScript and 17,330 bytes of CSS (gzip, aggregated across the site). The test fixture route is absent after the test runner restores the production build. The existing 1376×768 social image is retained and checked.
